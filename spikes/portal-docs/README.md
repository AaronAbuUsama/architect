# Spike: the portal as a generated docs site

**Question.** What does the portal look like as a static docs site generated from the blueprint, with live proof
layered on top (Aaron, 17 November 2026: "the portal is a static thing and it gets generated by that generator, but it
just comes into a better docs site")? It is the look for `design/briefs/F3-portal-upgrade.md`.

**Open it.** `python3 -m http.server 8978 -d spikes/portal-docs`, then http://localhost:8978.

**What is real.** `data.js` is acme's real `generated/portal/blueprint.json` from origin/layer/3 (`python3 data.py`
rewrites it). Every page, field, type, machine, event, error, code, role and environment comes from it, and so do the
23 generated Markdown pages. **What is not.** `evidence.js` is an illustrative `/_portal/v1/snapshot` answer (a budget
edit made spend stale in staging and production; invitation.send failed in staging; api-key.create is unproven in
production). The hashes in it are acme's real old and new hashes for spend.

**The seam.** Top right, "Static file" shows the page as the generator writes it: every proof is an empty slot.
"Served" shows it as the Worker fills the slots from the snapshot. "Seams" outlines every slot. Nothing else on a page
changes between the two.

**Not in it yet.** Journeys and worlds (waiting on F2.2's projection), per-eval results, traces, release history.
This is throwaway code: hand-written HTML and JS, not Fumadocs, and never imported by packages.
