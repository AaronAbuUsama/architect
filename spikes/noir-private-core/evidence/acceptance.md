# Independently authored acceptance checks

These checks were written before the private core implementation. They specify evidence to collect; they do not claim that a check has passed. The builder does not edit the checks. TXE checks are in `contracts/private_core_test/`. The network journeys below use separate ephemeral PXEs and generated keys held only in memory.

## Empty-handler proof

Before building handlers, compile a contract with the agreed signatures and empty private handlers, with `spend` returning zero and `read_right` returning `(false, 0, 0, 0)`. Run `aztec test --package private_core_test`. The active-right assertions and expected-refusal tests must fail. Save the command, exit status and individual results. A compiler or fixture failure does not establish that empty handlers fail the semantic checks.

## Network journeys

1. **Undeployed private organisation and real custody.** Register the shared contract class once. Construct a keyed instance locally, with initialization arguments committing the administrator and token. Register that same instance and shared secret on the administrator's and members' devices without publishing the instance. Initialise privately. Deposit a real standard Token privately, read the same pool balance from each internal device, and transfer privately to a separate recipient device. Assert the receipt succeeded, the recipient received exactly the sent amount, and the pool lost exactly that amount. Before and after, ask the node whether the organisation instance is publicly deployed. List every setup publication separately from each operational transaction. A local `registerContract` call is not chain publication.

2. **Shared custody without shared authority.** Give the administrator and both members the pool secret. Grant one right per member. Have one member try to grant, raise their own limit, and revoke somebody else. These must produce typed `AllowanceNotAdmin` refusals. The administrator must consume another member's active right successfully. A revoked member still reading private state is an expected consequence of retained shared custody; report it explicitly.

3. **Instant revoke and both same-block orders.** Prove a member spend and hold the transaction. Revoke that member and wait for the revoke to land. Submit the held spend, assert rejection, and retain the sanitised exact rejection category. Separately prove spend and revoke against the same current right note, submit both under controlled block production, and report both submission orders with their actual block numbers. Assert they cannot both land against the same note. Revoke first must block the spend. Spend first may make the stale revoke fail; show that the member is still active after the failed revoke, then sync and re-prove the revoke to consume the successor right. Do not describe the losing revoke as effective or promise that revoke always wins a race. Distinguish node admission rejection from in-block rejection or transaction dropping.

4. **Independent monthly budgets and refusals.** Grant different limits. Spend repeatedly through real token transfers for each member, checking each new right total and both token balances. Spending by member one must not reduce member two's own right. Try remaining plus one and assert typed `AllowanceExceeded` with the exact private `remaining` value available to the caller. Try a non-member, an admin without a right, a revoked member with the shared secret, and an outsider without it. Assert no token movement on each refusal. Report a lower-level missing-key error separately from a typed membership refusal if the outsider cannot discover a note. Race two spends by the same member and show at most one consumes the old right. Run independent-member spends too, and separate any shared-token-note conflict from per-member allowance conflicts.

5. **Month boundary and ordinary lifetime.** On a fresh network, move L1 in steps shorter than 23 hours, mine a successful L2 transaction after each step, and mine enough L1 blocks for L2 finality to catch up. Prove just before the end of a calendar month, hold the transaction, move past midnight, and submit. It must land and debit the old anchor month. Compare the proven and gossiped lifetime with an ordinary sponsored transaction made from the same anchor, without delayed-public reads or a month-expiry cap. Confirm the private core introduced no shorter expiration. Make another spend using a new-month anchor and confirm its new monthly total. Record that this time rule allows an old anchor inside the protocol's ordinary validity window. TXE does not establish network expiration behaviour.

6. **Public effects and gossip, for four operations.** Capture grant, revoke, spend and deposit before submission and after inclusion. Retain the actual public serialization or a complete field-by-field enumeration, not only a substring test. For each, enumerate fee payer, transaction fee, anchor, expiration, protocol/chain identifiers, note commitments, nullifiers, encrypted private logs and their field lengths, public logs, public-data writes, L2-to-L1 messages, public call requests, teardown calls, public function calldata, proof bytes/length and any class-registration data. Include counts and padding as observed. Scan full serialized fields and bytes for organisation, every party, token, amounts and role values in decimal and field-width hexadecimal forms. Short numeric coincidence does not itself identify a leak; explain any structural field that conveys a value. Compare at least one lifetime to an ordinary sponsored transaction. Report any operation fingerprint from counts, lengths or gas, even if no plaintext identity appears. Transaction timing, fee, size, counts, commitments and the shared payer remain public; do not claim literal invisibility.

7. **Measured operations.** Run each successful grant, revoke, spend and deposit several times with fresh applicable rights and synced PXEs. Preserve per-run prove-only, prove-step and total operation timing. Report sample count, median and worst for each. Keep setup, clock manipulation and deliberately held/racing transactions separate. State CPU architecture and proof-verification mode. Real client proving on a network configured to skip verification does not prove that a verifying network accepted the proof.

8. **Telemetry and library logs.** Install an attribute allowlist and record no private arguments, values, raw assertion messages or refusal payloads. The typed error's `remaining` remains caller-local. Export only the refusal tag. Track generated private keys, shared key, all party and instance addresses, amounts, limits, running totals and private identifiers in memory. Scan every span property, annotation, event, link and failure status, plus every captured library log line, in decimal and hexadecimal forms, before writing evidence. This includes serialised Effect causes, which can retain typed payloads even with safe attributes. A privacy check passes only if every observed private value has zero hits; never write a key into the scan report. Record log level and capture scope. Report unsampled verbose/debug logging and networking/IP anonymity as untested.

## TXE invocation and fixture requirements

Run from `spikes/noir-private-core/contracts` after compiling `private_core_contract` and adding `private_core_test` to the workspace members:

```sh
aztec compile
aztec test --package private_core_test
```

The fixture pins aztec-nr to `v5.3.0`. It uses `TestEnvironment`, creates a fresh random organisation secret in memory, and passes the name and arguments from `PrivateCore::interface().constructor(admin, token)` to `txe_oracles::deploy`. It then invokes that constructor explicitly through `env.call_private_opts` with the pool as an additional scope. This preserves the committed initializer arguments while supplying the shared key scope that the version 5.3.0 initializer helper omits. Every adversarial private operation also supplies the pool as an additional scope. The placeholder token is an ordinary light-account address: TXE cases only exercise guards which must refuse before any token call. No successful spend is claimed by these checks. The independent network journey must use the actual Token contract. `read_right(member)` exposes `(active, limit, spent, month_index)` only as a caller-local utility result. A tombstone or absent right is acceptable after revoke; no active right is acceptable after none/revoke.
