# Spike: the portal's information architecture (F2)

**Question.** How should the portal organise what the blueprint declares (things, operations, machines, events,
errors, roles, values, journeys, worlds, environments, releases) so a person and an agent can understand it, see what
is proven where, and follow work, using only facts the model and logbook actually hold?

**Tried.** Four IA models (catalog, lifecycle, graph, work), drawn with acme's real names in
[sitemaps.html](sitemaps.html). The recommended one, a catalog of things with proof, work and docs as lenses, is a
clickable mock in [index.html](index.html): home, thing, operation, machine, event, environment, board and the
reference indexes, all rendered from acme's generated model.

**Found.**
1. The model's own shape (things own machine, events, errors, roles; proof depends on the thing's hash) makes things
   the natural hubs. Every must-have section renders from today's model; nothing is invented.
2. Journeys and starting worlds are the biggest gap: the compiler skips them on purpose, so the operation page's
   "journeys that call it" and the board's Cover column need a display-safe projection (F2 §8).
3. Evidence beyond one aggregate verdict per operation (per-eval rows, timestamps, traces, release history) does not
   exist; the mock shows "unavailable" by default and labels its illustration.
4. HeroUI Pro has a Kanban (F1's audit missed it); the board is derived, so it needs no drag either way.

**Decision it supports.** `design/decisions/F2-portal-ia.md`.

**Open risks.** Fumadocs inside a non-Fumadocs shell is unverified. The source parse in `fixtures.py` is a throwaway
stand-in for the compiler projection, not a contract.

## Run and check

Open `index.html` or `sitemaps.html` directly in a browser; no server, network or account is needed. From the
repository root:

```sh
python3 spikes/portal-ia/fixtures.py --check   # acme-data.js matches examples/acme at 92bb0fa
for f in spikes/portal-ia/*.js; do node --check "$f"; done
```

`acme-data.js` is generated by `fixtures.py` from acme at `92bb0faa9529f1c81334650cff09670cf6e36d5a` (`origin/layer/3`):
the generated model, edges and docs byte-for-data, plus journeys, worlds and handler files read from source and
labelled so on screen. Evidence is "unavailable" unless the labelled illustration is picked. The mock is original
HTML/CSS/JS with no HeroUI Pro source; the purple tags name the component each section maps to (F2 §4).
