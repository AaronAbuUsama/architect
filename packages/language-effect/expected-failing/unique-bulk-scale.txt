# S-35 (design/goals/03-snags.md): the unique check of one call that wrote n rows rescans every written row for each row it checks, so a 3,000-row write costs about n x n key looks. Each test below passes once the check indexes the call's held rows by rule and key once, so each lookup is constant time. The 40,000-row test also needs the 3,000-row time test to pass first, and catches a pairwise scan on keys worked out once. The controls (a duplicate inside the write, a duplicate of a stored row, scope, a row released in the call, two rules on one thing, findBy over written rows, the floor on the counts) pass today.
