## 1. Kit format and runtime imports

**Decided.** A kit is an installed package with a pure descriptor, pure exported
declarations, and separate target/host runtime entry points. A project selects it
once in `blueprint/kits/<alias>.ts`. Choices are schema-checked, canonical JSON;
secrets are references by name, never values in that file.

For example, a descriptor exports one `Fixture` value:

```ts
import * as declarations from "./blueprint.js";

export const Fixture = {
  choices: Choices,
  defaults: { prefix: "" },
  declarations,
  sources: {
    declarations: "@fixture/echo/blueprint",
    worker: "@fixture/echo/worker",
    node: "@fixture/echo/node",
  },
} satisfies KitDefinition<typeof Choices>;
```

`KitDefinition` belongs to blueprint and imports only Effect. The descriptor
imports neither runtime entry. `sources` contains module specifiers, not declared
operation names. Worker and Node entries are optional capabilities; requesting an
unsupported runtime fails explicitly. Compiler/generator modules remain forbidden
in production, even if a descriptor names one.

The declaration entry exports namespaces, one per thing, so two things can both
export a `create` operation. Each namespace exports exactly one thing declaration
and its named operations, reads, errors, events and roles. Namespace/export
identifiers supply names, and object references supply relationships. Shared
values have a separate `values` namespace. A service-only kit may have no things.
The public wire declarations are static; choices configure services and handlers,
not arbitrary import-time schema mutation.

```ts
// @fixture/echo/blueprint
export * as echo from "./echo.js";

// A project command, for an already installed exact package:
// architect add kit @fixture/echo --as fixture

// blueprint/kits/fixture.ts, scaffolded once:
import { Blueprint } from "@architect/blueprint";
import { Fixture } from "@fixture/echo";
export default Blueprint.kit(Fixture, { prefix: "" });
```

`add kit` resolves one descriptor export, or accepts `--export` when selection is
ambiguous. It decodes defaults before writing, creates one choices file without
blanks, supports dry-run, and refuses an existing destination without overwriting.
Standard short names resolve to the standard library's public subpaths; they do
not cause a project to wrap the underlying library.

### Names and provenance

Canonical identity, generated identifiers and physical paths are separate:

| Purpose | Example derived by the compiler |
|---|---|
| Selected kit | `kit:fixture` |
| Thing | `kit:fixture:echo` |
| Operation | `kit:fixture:echo.repeat` |
| Generated path | `kits/fixture/echo` |
| TypeScript identifier | `KitFixtureEcho` |
| Declaration provenance | module `@fixture/echo/blueprint`, exports `echo`, `repeat` |

Keep the existing dot separator between thing and verb. Do not turn a canonical
name into a file path or strip punctuation to obtain an identifier. Validate
aliases, namespace/export names, generated paths, identifiers and code collisions
before generation, with both sources in diagnostics. Error wire tags continue to
come from exported class identifiers; qualified model references are separate.
Do not stamp alias-qualified names onto shared error classes: `ErrorNames.name`
uses a non-configurable symbol and Node caches package modules across projects.
Reject ambiguous error tags in an operation's error union and duplicate final
codes. Derive default error prefixes from the thing export, not the literal
`kit:` prefix. Initially reject mounting one singleton descriptor twice in a
model; do not claim independent instances without a declaration factory.

### Runtime wiring

The selected Worker entry exposes a lazy runtime factory taking decoded choices
and the selected declarations. It returns handlers grouped by the declaration
namespaces and an Effect layer. Construction performs no I/O. The generator wires
finished kit handlers rather than scaffolding project blanks for them. It retains
the layer's service Context for both HTTP and MCP, following the existing captured
Context pattern or `Layer.provideMerge`; `Layer.provide` alone is insufficient.
The Node entry is isolated for client-side work such as the keystore. Its command
contract is decided at L3.02, before its first use.

**Generated-import rule amendment.** In addition to the target runtime, blueprint,
host and project code, generated code may import the declaration-only entry and
the matching target/host runtime entry explicitly declared by a selected kit.
API/SDK/browser code may import only the declaration entry. Worker code may not
import the Node entry. Direct imports of a kit's wrapped packages remain
forbidden in project code. Check the actual import closure; do not rely on tree
shaking. This does not permit arbitrary runtime imports or build-only packages.

**Evidence and alternatives.** Current `model/internal/layout.ts` rejects `kits/`;
API/server generation reconstructs project paths; `render/internal/names.ts` only
normalizes dashes. A project bridge adds another hand-written file to the
one-choices-file contract, while target/host reexports couple those packages to
each kit. Explicit selected entry points keep that dependency outside the core.
Spike `kit-package-exports` at `c9be9c83` proved packed-package resolution, type
declaration emit, project typechecking, configured real workerd execution, and
negative client/Worker crossing checks. It also exposed the Effect layer Context
issue. Independent source/receipt review passed. The experiment used representative
generated shapes; it did not implement compiler support or establish portability
of the spike on Node 24/Linux.

## 2. One graph and effective source integrity

**Decided.** Operations declare consumed kit selections and dependency descriptors
by reference in `uses`. The compiler emits one normalized graph for generated
edges, `architect impact`, `Compare.dependsOn/hashOf` and release proof staleness:

```text
kit:fixture -> kit:fixture:echo.repeat     provides
kit:fixture -> allowance.grant            used-by
dependency:pricing.quote -> allowance.grant  used-by
```

The compiler follows these references transitively, sorts and deduplicates edges,
and rejects dangling references and cycles. A dependency's selected declared
errors join its consumer's declared error union; conflicting tags/codes fail
rather than silently choosing one. Generated handler service requirements include
only declared consumed services, so a caller cannot hide a kit use from the graph.
Impact must print the edges, not merely write an unused JSON file.

Kit/dependency hashes include normalized declarations, decoded choices, runtime
mode, provenance, exact resolved package identity, and effective source integrity.
Functions and Effect layers are not JSON-hashed. Include the selected runtime and
dependency mapping implementation bytes. Published lock integrity alone cannot
stand in for changed workspace code under version `0.0.0`. A conservative stable
hash of the effective package files and resolved dependency identities is allowed;
document that a package change can stale all its selected kits. Do not hash
absolute local paths or transient build/run outputs. A package without a usable
integrity source fails closed.

Changes stale the affected operations and graph consumers, not unrelated project
operations. Existing model-diff rules still classify wire changes; metadata-only
integrity/choice changes are patch changes and must not disappear from comparison.
Kits-free models and their earlier generated interfaces remain compatible; absent
kit/dependency graph fields read as empty in retained models.

## 3. Dependencies cover non-Effect libraries now

**Decided.** The initial command selects one installed package, one named callable,
one alias, a step kind, and existing declared error classes. Promise mode is the
default; `--mode effect` selects a typed Effect callable. Do not narrow the
primitive to Effect-only fixtures or invent arbitrary SDK/type reflection.

```sh
architect add dependency @fixture/remote \
  --export quote --as pricing --step network \
  --error blueprint/things/allowance/errors.ts#PriceUnavailable
```

The command resolves the exact installed project pin and selected exports before
writing. Error declarations already own their fields and exit codes; the command
does not invent a band or domain errors. Repeated `--error` selects a union. It
writes `blueprint/dependencies/pricing.ts` with exactly one blank:

```ts
// Scaffolded from @fixture/remote. Yours from now on.
import { Blueprint } from "@architect/blueprint";
import { quote as call } from "@fixture/remote";
import { PriceUnavailable } from "../things/allowance/errors.ts";

export const quote = Blueprint.dependency({
  package: "@fixture/remote",
  version: "1.0.0", // Actual resolved exact pin.
  mode: "promise",
  call,
  errors: [PriceUnavailable],
  step: "network",
  failure: Blueprint.todo("map the dependency failure to PriceUnavailable"),
});
```

Argument and answer types come from the imported callable. Promise failures are
`unknown`; Effect mode also preserves the callable's typed failure and service
requirements. The mapper returns only an instance of a selected declared error.
The generated injectable service names this call `dependency:pricing.quote`,
adds its span and deciding refusal log, and counts the work. Do not log foreign
failure payloads by default. The descriptor performs no call during import.

Promise mode lazily invokes the callable inside `Effect.tryPromise`. Synchronous
invocation exceptions and Promise rejection enter the `unknown` failure channel.
Only that raw wait is `Effect.uninterruptible`; `Effect.mapError(failure)` stays
outside it, so a mapper bug remains a defect. This generic mode injects no signal
and promises no SDK cancellation. Interruption is deferred until the returned
Promise settles, preserving counted work rather than falsely reporting quiet.
A never-settling Promise prevents draining; settlement guarantees only the selected
callable's completion, not remote-system or detached background-work quiescence.
Known cancellable SDKs use an explicit Effect adapter with their actual signal and
timeout contract, as std/chain will do.

Effect mode uses `Effect.suspend` and `Effect.mapError`: map typed failures only;
preserve success, defects, interruption and service requirements. Never use
`catchCause` to manufacture project refusals. Effect 4.1.1 source confirms these
semantics, including deferred interruption and `BusyLive.counted` retaining its
token until protected work finishes. The author must verify them with a real HTTP
hold/release fixture and negative missing-mask case, plus Effect failure/defect/
interruption/mapper-bug cases. Source review is not that runtime proof.

## L3.01 author and builder boundary

Before any builder, a separate author records failing checks on the current empty
implementation for one-command kit selection, real generated SDK/workerd calls,
typed SDK output, no project kit-handler blank, configuration, import closures,
namespace/code collisions, graph/impact and source-integrity staleness. Include
the raw Promise dependency fixture as well as Effect-mode guards, exactly one
mapping blank, dry-run/duplicate refusal, and earlier kits-free behavior.

Only after these checks fail does a builder implement L3.01. Its finish line
remains the build plan's: a fixture kit is added with one command, its operations
appear in the generated SDK, and impact shows kit-to-consumer edges. New primitives
retain all nine evals and their planted checks. This decision does not mark any
L3.01 implementation or Gate 3 complete.
