# D1: runtime, storage and toolchain

Decided 16 November 2026 by the conductor (Aaron gave the agent architectural ownership). Evidence:
`design/wayfinding/stage-1.md`, `spikes/durable-object.md`, `spikes/world-clock.md`.

1. **Who owns a thing's state:** `lives: database | actor | chain` in the language. `database` (D1, with a version
   column) is the default and is built in layer one, along with `actor` (a Durable Object with a lock of one permit).
   `chain` arrives in layer four. *(18 November 2026: widened by [`K3`](K3-stores-and-sources.md): homes are stores of
   open kinds, and a system we don't own is reached through an adapter.)*
2. **The local host:** workerd, through `wrangler dev` and `@cloudflare/vitest-pool-workers`, behind a `Host` service.
   Everything runs for real. Nothing is mocked.
3. **Storage:** D1 through `@effect/sql-d1`, each Durable Object's own SQLite through `@effect/sql-sqlite-do`, and R2
   for exports (Aaron's call).
4. **Effect:** `effect@4.1.1` and its 4.1.1 satellites, pinned exactly. Effect 4 holds HTTP, HttpApi, the CLI and SQL
   in `effect/*`. Services are `Context.Service`. Telemetry leaves Workers through `effect/observability` OTLP.
5. **Toolchain:** **TypeScript 7.0.2 compiles and type-checks everything** (Aaron: 7's speed matters). Nothing that
   imports TypeScript as a library supports 7 yet: Nx core (`readConfigFile` in its project graph) and the
   typescript-eslint utilities under the boundaries plugin. So `typescript` is aliased to
   `@typescript/typescript6@6.0.2`, Microsoft's compatibility package that serves the 6.0 API to those tools, and
   `@typescript/native` is `typescript@7.0.2`, whose `tsc` is the one every check runs. Drop the alias once Nx and
   typescript-eslint support 7.1's API. Vitest `4.1.12` with pool-workers `0.23.0`; `@effect/vitest` isn't used,
   because it needs vitest 5, so a small local Effect test helper stands in. Nx `24.0.3`. Lint is oxlint `1.90.0`
   with the boundaries plugin (no ESLint).
   - **Nx stays.** Dropping it was weighed. The TypeScript 7 problem didn't need it gone. Nx gives us the sync
     generators whose drift check is free, `nx g` with dry runs, the preset and `create-nx-workspace`, the project
     graph behind the package rules, and caching. The design is built on all of those. A homemade generator library
     would rebuild them.
6. **Async in tests:** test files and `main.ts` files are entry files, so they may run promises at the edge.

**Settled in L1.01:** module boundaries hold under oxlint 1.90 with `@nx/oxlint/boundaries-plugin` 24.0.3, so ESLint
isn't used at all. Planted fixtures sit in `test/fixtures/` (ignored by lint and typecheck), and the lint package's
test lints them with the same config, with that ignore removed.
