# D2: the layer-one primitives, and stage one's slice of acme

Decided 16 November 2026 by the builder (Aaron gave architectural ownership). Evidence: the worked example in
`design/docs/index.html`, `design/spikes/names-from-paths.md`.

## The build plan's four recommendations stand

1. **Moves with several outcomes:** `to` takes a list. The handler picks the outcome, and the runtime checks it
   against the list.
2. **Reads:** `Blueprint.read`, answered from the thing's records, with no handler.
3. **Idempotency:** `idempotent: "request"`, keyed by a request-key header. A retry replays the stored answer.
4. **Starting worlds** run declared operations and never write rows.

## Fixed while reading the design against AGENTS.md

5. **Steps take their names from their keys, not from strings.** The docs wrote
   `steps: [Blueprint.step.database("allowance.grant.insert")]`, which writes a declared name as a string. It is now
   `steps: { insert: Blueprint.step.database() }`. The compiler names the step `allowance.grant.insert` from the path
   and the key, and the handler calls `steps.insert(...)`, as the docs' handlers already did. The docs are updated to
   match.
6. **Field paths in roles stay typed strings.** `owner.of("organization")` names a field of the payload, checked by
   TypeScript against the payload's keys. A field key isn't a declared name.

## Stage one's slice of acme

Stage one proves the whole chain on real operations, not on one in isolation:

- **Things:** `person` (fields only; people arrive through sign-in in stage two), `organization` (verb `create`; its
  creator is its owner; role `owner`), and `allowance` (verb `grant`; machine with the `grant` move into `active`;
  event `AllowanceGranted`).
- **A data refusal on grant:** `AllowanceLimitTooHigh`, exit 44, when the limit is over the organisation's cap. Grant
  then has a declared error and a deciding log, so every eval has something real to judge in stage one.
- **Principals:** the world issues each journey's cast a real signed token (HMAC through WebCrypto inside the world
  Durable Object), carrying `person`. Better Auth replaces the issuer in stage two, and the rest stays the same.
- **Starting world `founded`:** ada runs `organization.create`. Journey `grant-an-allowance`: ada grants olga 500;
  bob is refused (`NotAllowed`) and the handler never runs; a limit over the cap is refused with
  `AllowanceLimitTooHigh`.

## Settled while building L1.10

7. **Imports inside a package go through Node subpath imports:** `#modules/<module>/<file>.ts`, declared in the
   package's `package.json` `imports`. That follows `~/AGENTS.md`, which says to use an alias and never `../..`, and it
   resolves the same way under tsc, vitest, Node and wrangler's bundler, since each package resolves its own `#`. A
   `~/` tsconfig path wouldn't, because packages are consumed as source. The Nx boundary rule runs with
   `allowCircularSelfDependency: true` so that it accepts these. Test files (`*.test.ts`) may also import
   `vitest`.
8. **No module imports another module's `internal/`.** `structOf` is exported from `things/service.ts` for events,
   errors and operations. Lint will enforce this rule (L1.40).
9. **Roles of different things compare as `Role<any>`.** A role's rule takes its own thing's instance, so a list of
   roles from different things can only be typed loosely. The precise check is on the path: `owner.of("organization")`
   must name a payload field, or the operation doesn't compile.

## Settled while building L1.11

10. **The model describes values, not JSON Schema.** The build plan said payload and answer schemas as JSON Schema.
    Effect 4.1.1's `Schema.toJsonSchemaDocument` drops an id's prefix pattern and a uint's bounds, so JSON Schema in the model
    would lose what the generators need. Each field carries its value's description instead (`{type: "id", prefix}`,
    `{type: "uint", bits}`, `{type: "text", max}`), plus `named` for a named value and `ref` for a field taken from
    another thing. The generators derive JSON Schema (OpenAPI, MCP) from these at generation time. Evidence:
    `design/evidence/L1.11/03-architect-model-json.txt`.
11. **Refusals are computed in the model.** An operation's refusals are its declared errors, then
    `<Thing>Not<FirstState>` when its move has a `from`, then `NotAllowed` unless anyone may call. Every generator reads
    the same list.
12. **Planted fixtures stay out of the Nx graph** (`.nxignore`: `**/test/fixtures/**`). The blueprint fixture that
    imports the compiler, which is wrong on purpose, otherwise makes Nx see a real cycle once the compiler imports the
    blueprint. The boundary test still lints the fixtures directly, and still catches them.

## Settled while building L1.12

13. **A uint travels as a decimal string.** `Blueprint.uint(bits)` is `Schema.BigIntFromString` with its bounds: a
    `bigint` in code, a string on the wire, because a JSON number loses precision above 2^53 and an amount is 128 bits.
    The test sends 2^128 − 1 through the wrapper into D1 and back unchanged
    (`design/evidence/L1.12/03-workerd-and-real-d1.txt`).
14. **Only declared errors are errors.** A handler's error channel is its declared errors and nothing else, so a
    database failure inside a step must die (`Effect.orDie`). It reaches the caller as a 500 and the trace as a defect,
    never as a refusal. A host layer that can't be built (a missing binding) dies the same way.
15. **The wrapper takes its name from the generated code.** `Handlers.serve({ name, operation, handler })`: the name is
    the one string the compiler writes into `generated/`. The wrapper runs the handler as counted work (`Busy`), opens a
    span named after the operation with `payload.<field>` and principal attributes, gives each step a child span
    `<name>.<key>`, and checks the answer against its declaration (outside it dies, as the handler's bug).

## Settled while building L1.13

16. **The generator reads the model from a fresh process.** `@architect/generators:sync` runs `architect-model`
    (`packages/compiler/src/main.ts`) for each project with a `blueprint/`, then renders. Importing the blueprint
    inside the generator would let the long-lived Nx daemon keep files it imported before an edit. Generators read
    only the model, never the blueprint itself.
17. **Generated code reuses the declarations, never copies them.** An endpoint's payload and answer are the
    operation's own `payloadSchema` and `answerSchema`, imported from the blueprint file by path; the handler type is
    `Handler<typeof declaration>`. Only names and the wire error classes are written out. A wire error is a
    `Schema.TaggedError` built from the declared class's fields: 422 for a declared error, 409 for a machine's
    `<Thing>Not<State>`, 403 for `NotAllowed` (exit 3). `Wire.refusals` maps one to the other by name.
18. **The layout in a project:** `generated/{model,api,server,sdk,cli}` regenerated on every sync, orphans removed;
    `implementation/handlers/<thing>/<verb>.ts` scaffolded once, never overwritten, returning `Handlers.blank(...)`
    until written. The CLI is `<project> <thing> <verb> --<field>`, each flag text that the declaration decodes, so a
    bad id is refused (exit 2) before any call. The generated CLI prints only through `Console` and sets its exit
    code through an `ExitCode` service its entry provides.
19. **The server captures its services when routes are built** (`Effect.context` in each group), as the spike did, so
    `toWebHandler` needs nothing per request. Principals are anonymous until `architect dev` provides the world's
    signed tokens (L1.14).
