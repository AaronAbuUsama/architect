I built the allowance as a private Aztec.nr contract on Aztec 5.3.0, and the same target pattern works. All six jobs run: generated types and refusals, a compiled machine over private notes, a filled scaffold, conformance tests in the TXE, and an Effect client on Aztec's local network. Everything ran in `/tmp/spike-noir`, with no repository, keys or spend.

**What it needs:**
- **Revoke needs its own design.** By default only the note owner's key can consume a note, so the owner cannot consume a note held by the member. The fix that works: one note per allowance, sent to both people, consumed with a random key stored in the note.
- **One step was missing from the client.** The member's device has to catch up with the chain before proving. Without that, the next move runs on stale state.
- **Time can't be pushed forward freely.** Private code only sees the last block's time, and a transaction must land within 24 hours of that block. On the local network, time only moved forward in steps under 24 hours.
- **The fee leaks who sent it.** Paying the fee from your own account writes a public balance change, which links the transaction to you.

**Two things to know before trusting the numbers:**
- **Install was done by hand.** The official installer was blocked because it edits `~/.bashrc`, so I repeated its steps manually with the same pinned versions.
- **The local network does not check proofs** (`realProofs: false`). The proofs were still really made on each device, so the timings are real. Nothing here shows a verifying network accepting them.

**Results:**
- **Conformance tests:** all 22 pass, plus 5 unit tests for the machine and calendar. The planted wrong test fails with `AllowanceCannotSpend { state: 3 }`, as it should.
- **Local network:** deploy, grant, spend and revoke all run from Effect. Each device saw the right amounts and the outsider saw nothing.
- **Monthly reset:** it worked on the network. Right after moving the clock to 1 December, the spend was still refused, because the last block was dated 30 November. After one December block it succeeded.
- **Double spend:** two spends proved from the same note were both sent; the second was rejected with `Existing nullifier`.
- **Leak check:** none of the 23 private values appeared in the 150 recorded spans, or in the Aztec library's 232 log lines at `info` level. At `debug` level the library does log note contents.
- **Timings** on 4 CPUs and no GPU: proving takes 7.5–10 s and a whole operation 12–15 s at the median.

Not tested: moving real tokens or messages between L1 and L2, private code checking the current time, an expiry rule, proving in a browser, and a network that checks proofs.

# TO THE LEAD

## 1. README

### Question
Can Architect's target pattern produce the allowance as a **private** Aztec.nr contract, doing the same jobs on Aztec's local network?
- generated types, events and refusals
- a compiled machine over private note state
- a scaffold with blanks that get filled
- conformance tests in the TXE (Aztec's Noir test environment)
- an Effect client over the generated artifact

And which new primitives does that force?

### Answer
**Yes, if** Architect adds these:
- **Visibility on fields and events**, as a list of roles that may read.
- **Who may consume the state**: a rule for which roles can use up a note.
- **Where an operation runs:** `runs: "client"`.
- **Two new client steps:** `sync` and `prove`.
- **Private time:** the time of the last block, plus a 24-hour limit.
- **A rule for who pays the fee.**

The machine, the refusals, the tests and the Effect client carry over almost unchanged.

### What was tried
- **Install:** the Aztec toolchain 5.3.0, installed natively by hand. That was the newest release at least two weeks old (published 26 October 2026). The official installer was blocked because it edits `~/.bashrc`, so I repeated its steps.
- **Generated files:** types, refusals, the machine as a step function, a month calendar, and the note. Each starts with `// Generated from the blueprint. Do not edit.`
- **The contract:** the scaffold, filled. Amounts live in a **private ledger of spent amounts**; there is no token transfer.
- **A deliberately naive variant**, to show that revoke fails with Aztec's default note.
- **Tests:** 22 conformance tests in the TXE, plus 1 planted wrong test.
- **Effect client and runner:** a client in `effect@4.1.2` over the artifact generated by `aztec codegen`. A runner with three separate devices (owner, member, stranger), each with its own wallet, keys and PXE (Aztec's private execution environment on the device). It runs the scenario on `aztec start --local-network`.
- **Time:** moved forward with `EthCheatCodes.warp` plus filler transactions.
- **What the chain shows:** read from the node with `getTxReceipt(..., {includeTxEffect: true})`.
- **Leak checks:** over the recorded spans, and over the library's logs at `info` and `debug` level.

### What was found

1. **The machine compiles into a step function, the same as in Solidity.**
   - States and moves are `u8` constants.
   - `step(from, move, to)` refuses an undeclared move with the generated refusal, and refuses an undeclared target with `AL-099`.
   - Refusals are assertion messages of the form `[AL-002] AllowanceCannotSpend { state: 3 }`. The client decodes them into `Schema.TaggedError`s.
   - **Evidence:** check 1. Every declared move from every state passes. Every undeclared move is refused with the right generated refusal. The planted test fails with `Assertion failed: [AL-002] AllowanceCannotSpend { state: 3 }`. On the network, checks 3.1–3.5 and 2.5–2.6 return the typed errors.

2. **Aztec's default note makes revoke impossible.**
   - A note's nullifier (the one-time marker that shows a note was used up) is `H(note_hash, nhk_app(note owner))`. It comes from the `#[note]` macro in `aztec-nr/aztec/src/macros/notes.nr:84-93`.
   - So only the note owner's device can consume the note. Delivering the note to the grantor lets them *read* it, not *use it up*.
   - **Evidence:** the TXE test `naive_owner_cannot_nullify_members_note`. The owner's device sees the note (`naive_count = 1`), but `naive_revoke` fails with `Key validation request denied: no scoped account has a key with hash 0x0d3f…`.

3. **The revoke design that works:** one note per allowance, sent to both people, with a custom nullifier `H(note_hash, nullifier_key)`.
   - `nullifier_key` is random, chosen at grant, and stored inside the encrypted note.
   - Both roles can therefore consume the note. *Which* role may take *which* move is enforced in the circuit by the role checks (`assert_owner`, `assert_member`).
   - **Evidence on the network:**
     - The owner revoked (check 2.4). The member's own device then shows `state: 'revoked'`.
     - A later spend by the member gets `AllowanceCannotSpend {"state":3}`. A second revoke gets `AllowanceCannotRevoke {"state":3}`.
     - The owner's device also follows the member's spends (check 5.2: the owner sees `spent: 1013n`). That's because the owner can compute the nullifiers.
   - **Trade-off:** anyone who holds the note's plaintext can consume it. So the note must only ever be sent to the roles that may move it.
   - **Alternative not built:** a public revocation flag in a `DelayedPublicMutable`. Private code can read it, but the revoke only takes effect after a delay, and the revoke itself is a public write.

4. **"Not granted yet" cannot be proven in private code.** Private code cannot prove that something is absent; it can only prove that something exists.
   - `grant` therefore has two layers:
     - a refusal based on the owner device's view (`AllowanceCannotGrant { state }`)
     - a constrained guarantee: a nullifier that only the owner can compute, `H(nhk_app(owner), member, "grant")`, which can exist at most once
   - **Evidence:** check 3.5, `AllowanceCannotGrant {"state":1}`. The TXE tests `grant_from_*` pass for every state.

5. **Replay and double spend are blocked by nullifiers.**
   - Two spends proved from the same note before either was sent: the first was mined; the second got `Invalid tx: Existing nullifier`. The client turns that into `NetworkRejected`.
   - The TXE could not replay a note: its bare `private_context` has no account scope, so it can't read the member's note.
   - **Evidence:** check 6.1.

6. **Private code can only trust the timestamp of its anchor block** (the last block its device synced).
   - `get_anchor_block_header().global_variables.timestamp` is a *lower bound* on the real time. The protocol requires a transaction to be included within 24 hours of that block.
   - The lazy monthly reset is safe with a lower bound, because it only ever moves forward.
   - **Evidence in the TXE:**
     - `private_sees_anchor_time_not_now`: the next block is set to February but nothing is mined yet; the spend is still refused as exhausted.
     - `monthly_reset_on_next_touch`: after one February block, the spend works and the period rolls to `2030*12+1`.
   - **Evidence on the network:**
     - Check 4.3b: L1 is at `2026-12-01T00:05Z` but the anchor is `2026-11-30T05:46Z`, and the spend gets `AllowanceCannotSpend {"state":2}`.
     - Check 4.6: after one December block, the spend is `ok`, with state `active`, `spent: 1n` and period 24322 → 24323.

7. **Moving time on the local network is fragile.**
   - `EthCheatCodes.warp` works, but only in steps under 24 hours, each followed by a block.
   - One 15-day jump gave `Invalid tx: Invalid expiration timestamp` for *every* transaction, which made the network unusable until restart.
   - After warping, new wallets on that network failed with `Highest aged index (3) must not exceed highest finalized index (1)`, part of the device's message-tagging bookkeeping. The cause is the finalized chain falling far behind the warped clock.
   - The fix was to restart the network for each run, and to run the warp last.

8. **The client needs a `sync` step before `prove`.**
   - Calling `pxe.proveTx` directly does not auto-sync the device. The wallet's own `send()` path does.
   - Without the sync, the next private move ran against a stale anchor block. It either failed to find the note (`state: 0`) or re-used a note already consumed, then rejected with `Existing nullifier`.
   - **Evidence** from `diag2.ts`:
     - without a sync, the device stayed at block 20 while the node was at 22, and every spend failed
     - with `pxe.sync()` first, the anchor went 24 → 25 → 26 → 27 and four spends in a row succeeded
   - The generated client now runs `request → sync → prove → submit → wait`, each as its own span.

9. **Who can read private state can only be tested with one PXE per person.**
   - In the TXE, every account shares one PXE, and `ExecuteUtilityOptions.with_from` only sets `msg_sender`. So even the stranger read the note there (`(1, 100, 0, 24360)`).
   - On the network, with separate devices, the stranger saw `{ state: 'none' }` while the owner and member both saw the amounts (checks 5.1 and 5.2).

10. **Events must be declared inside the contract module.**
    - Events declared in a separate module compiled fine but were missing from the ABI, so the TypeScript generator emitted no `events`.
    - The generator therefore has to inject a marked "generated: events" region into the scaffold's contract module.
    - Each role in an event's visibility becomes one `deliver_to(...)` call, and the same goes for note copies.

11. **What anyone watching the chain (including an Architect server) sees for a private spend** (check 8.1):
    - tx hash, status and block
    - 2 note hashes, 4 nullifiers, 7 encrypted private logs
    - 0 public logs and 0 L2→L1 messages
    - **1 public data write**, and the fee
    - the contract address, owner and member do not appear in plain form
    - the function and the amounts do not appear

    That one public write is the fee payer's fee-juice balance. With the member paying their own fee, anyone who knows the member's address can compute that storage slot and link the transaction to them.

12. **Telemetry:**
    - The allowlisted spans contained none of the 23 private values (check 9.1).
    - Aztec library logs at `info` level had 0 hits in 232 lines.
    - At `debug`/`verbose` level, the device logged decrypted note contents and event payloads. The limit `987654321` appeared as `0x3ade68b1` four times.
    - Raw error messages contain private values. The opt-in device debug line showed `AllowanceExceeded { remaining: 103716 }`.

### The decision it supports
- Build target-noir along the same lines as target-solidity. The step function, generated refusals, conformance tests and Effect client all carry over.
- Before Noir arrives, add to layer one (Architect's core declarations):
  - visibility as a list of roles
  - a rule for who may consume
  - `runs:` on operations
  - `sync` and `prove` as step kinds
  - a declared private-time rule
  - a declared fee payer
- Do not try to port "the owner nullifies the member's state" literally. Generate the shared nullifier key from the declared roles instead.

### Open risks
- **Real verification is untested.** `realProofs:false` means the node does not verify proofs. Behaviour on a verifying network is untested.
- **Browser and mobile untested.** Proving there uses WASM and will probably be slower than the 7.5–10 s measured here.
- **The shared nullifier key needs a security review.**
  - The owner chooses the key through an unconstrained random oracle; malicious owners only hurt their own allowance.
  - Any holder of the plaintext can consume the note.
  - Revoke and spend race; the loser gets `NetworkRejected`.
  - Retry-after-sync is not tested.
- **Fee privacy is unsolved.** No fee-payment contract or sponsored-fee path was tried.
- **Time-based rules where an earlier time favours the caller are unsafe without more work** (an expiry, for example). The caller can pick an anchor block up to 24 hours old. Those rules need `set_expiration_timestamp` or `privately_check_timestamp`; neither was tested.
- **Aztec's APIs move fast.** Raw `pxe.proveTx`, `completeFeeOptions` and similar were reached through protected methods and may change.
- **Time-warp tests are fragile.** They need a fresh network.
- **Read access can't be checked in the TXE.** The conformance tests can't cover it, so the test plan needs a network check.
- **Cost:** 7 private logs per spend, because both roles get both the note and the event.

## 2. The new primitives

1. **Visibility per field and per event: validated, then refined.**
   - It is a **list of roles**, `private(owner, member)`, not a public/private switch. It compiles to:
     - a `deliver_to` call per role, for note copies and for events
     - the inherited visibility of arguments and refusal payloads
   - Events must live inside the contract module (finding 10).
   - **Evidence:** finding 10, checks 5.1/5.2 (the stranger sees `none`), and check 8.1.
   - **Refined further:** "who may read" (delivery) and "who may consume" (the nullifier rule, below) are **two separate axes**.

2. **Where an operation runs: validated.**
   - `runs: "client"`: the caller's own PXE executes and proves the operation, so it needs that person's keys.
   - Reads run on the device too, as utility functions.
   - The chain only receives the proof.
   - A server cannot run a private operation for a user without holding that user's keys.
   - **Evidence:** finding 2 (`Key validation request denied`), and the device-scoped results in check 5.

3. **Proving as a step kind: validated, then refined.**
   - A private operation runs as `request → sync → prove → submit → wait`.
   - `prove` is about 75–80 % of the total (7.5–10 s out of 12–15 s).
   - **`sync` must be its own step kind** (finding 8).
   - Submit can fail *after* a successful proof with `NetworkRejected` (finding 5).

4. **Private state as notes and nullifiers: validated, then refined.**
   - One note per thing instance holds the state plus the fields. Each move consumes the note and creates a new one.
   - The thing needs a **rule for who may consume**, which becomes the nullifier key (finding 3).
   - The "none" state can't be proven in private code, so each thing identity needs a **uniqueness nullifier** (finding 4). The refusal for "none" relies on an honest device.

5. **Privacy-safe telemetry: validated, with this rule.**
   - **Span attributes are an allowlist:**
     - the thing, operation, step and runs
     - the role
     - the outcome *tag* only
     - timings, circuit sizes and function counts
   - **Never record any of these:**
     - argument values
     - field values
     - refusal payloads
     - raw error messages
     - Aztec debug or verbose logs
   - **The tx hash is device-only:** it may be kept on the device, but is stripped before export. It's public on chain, so linking it to an operation and a role de-anonymises the transaction.
   - Cap Aztec library logs at `info` on any device whose logs leave it.
   - **Evidence:** finding 12 and check 9.

6. **What time private code can trust: validated, then refined.**
   - It is the anchor block's timestamp, which is a lower bound on the real time. A transaction is valid for at most 24 hours past its anchor.
   - A lazy move that only moves forward is safe with this time.
   - Getting a timestamp into the future requires blocks; tests must move time in steps under 24 hours.
   - **Evidence:** findings 6 and 7.
   - Checking the real current time through the public-checks contract (`privately_check_timestamp`) was **not tested**.

7. **Messages between L1 and L2: not tested.** The contract APIs exist: `message_portal`, `consume_l1_to_l2_message`, and the TXE's `send_l1_to_l2_message`.

8. **New: who pays the fee. Validated as a need; no solution tested.**
   - Self-paid fees write the payer's public fee-juice balance, which links the private transaction to the payer.
   - Operations need a declared fee strategy (`payer: self | sponsored | fee-payment contract`).

9. **New: a move must be sequenced against the device's synced state. Validated.**
   - Moves on the same thing must each start from a fresh sync.
   - Concurrent moves by two roles race at the nullifier, and the loser gets `NetworkRejected` (findings 5 and 8).

10. **New: peers must be registered on each device. Validated as necessary setup.**
    - Each device must `registerSender(peer)` and `registerContract(instance, artifact)` before it can find notes and events sent to it.
    - That is part of granting a role on the device. (Every run did this; it was not tested without it.)

11. **New: the TXE can't test who may read.** Validated: the conformance test plan must split into TXE tests plus network checks for access (finding 9).

## 3. An addendum for Architect's lead (validated only)

**What target-noir would generate:**
- For each thing, a `generated/` module containing:
  - states and moves as `u8` constants
  - refusals as coded assertion messages, `[AL-002] AllowanceCannotSpend { state: N }`
  - the machine as `can`, `is_edge` and `step`, plus helpers for lazy moves
  - a calendar helper for `every: calendar_month`
  - a custom note holding the fields, the state, the period and a `nullifier_key`
- **A scaffold** with:
  - storage as `Owned<PrivateSet<Note>>`
  - one private function per operation, with the role check, the pop/insert of the note, and delivery to every role in the visibility
  - a utility read model
  - a marked generated region inside the contract module for events
  - blanks only for domain logic
- **TXE conformance tests:** every move from every state, data refusals, the wrong signer, lazy time moves, and the anchor-vs-now rule.
- **An Effect client:** one `Context.Service` per thing over the `aztec codegen` artifact.
  - each operation is a span with `request / sync / prove / submit / wait` children
  - refusals become typed `Schema.TaggedError`s
  - network rejections become `NetworkRejected`
  - an allowlist-based redaction rule

**The new primitives and their proposed declaration shapes:**
- `visibility: "public" | private([roles])` on fields, events, operation arguments and refusal payloads. Extends fields, events and errors.
- `consumable_by: [roles]` on a thing's state. It becomes the shared nullifier key and the delivery list. Extends roles and things.
- `runs: "client" | "server" | "chain"` on operations; private Aztec operations are `client`. Extends operations.
- `sync` and `prove` as step kinds, with their own spans and timings. `submit` can fail with `NetworkRejected`. Extends operation steps and the Effect client.
- `time: anchor` for private code: a lower bound, valid for 24 hours. Lazy moves allowed only when they move forward. Extends lazy moves.
- `payer:` on operations. Extends operations.
- A redaction rule that is an attribute allowlist, with a device-only class. Extends telemetry.

**Cheap things to add to layer one now:**
- Make visibility a role list (default `public`) on every field, event, argument and error payload. Solidity just treats everything as public.
- Add `runs:` to every operation (Solidity: `client` signs, `chain` executes).
- Make spans in every target an allowlist, with no value attributes and the outcome tag only.
- Give refusal codes a format that is stable across targets, e.g. `[AL-002] Name { field: value }`.
- Keep the operation step list open to new kinds such as `sync` and `prove`.
- Let conformance tests carry a marker for "needs separate devices".

**Not validated here (keep separate):**
- the L1 money path and L2→L1 messages
- `privately_check_timestamp` and expiry-type time rules
- a `DelayedPublicMutable` revocation flag as the alternative revoke design
- fee privacy through a fee-payment contract or sponsored fees
- retry-after-sync after `NetworkRejected`
- proving in a browser or on mobile
- behaviour on a network that verifies proofs

// Generated from the blueprint. Do not edit.
// The `allowance` machine compiled into a step function. The contract MUST call `step` for every state
// change; `step` refuses any move that is not declared from the current state, with the generated refusal.
//
//   grant  : none               -> active
//   spend  : active             -> active | exhausted
//   revoke : active | exhausted -> revoked
//   reset  : active | exhausted -> active          (lazy, on next touch, when the calendar month rolls)
use crate::generated::types::{
    MOVE_GRANT, MOVE_RESET, MOVE_REVOKE, MOVE_SPEND, STATE_ACTIVE, STATE_EXHAUSTED, STATE_NONE, STATE_REVOKED,
};
use crate::generated::errors;

/// Whether `mv` is declared from `from`.
pub fn can(from: u8, mv: u8) -> bool {
    if mv == MOVE_GRANT {
        from == STATE_NONE
    } else if mv == MOVE_SPEND {
        from == STATE_ACTIVE
    } else if mv == MOVE_REVOKE {
        (from == STATE_ACTIVE) | (from == STATE_EXHAUSTED)
    } else if mv == MOVE_RESET {
        (from == STATE_ACTIVE) | (from == STATE_EXHAUSTED)
    } else {
        false
    }
}

/// Whether `from --mv--> to` is a declared edge.
pub fn is_edge(from: u8, mv: u8, to: u8) -> bool {
    if mv == MOVE_GRANT {
        (from == STATE_NONE) & (to == STATE_ACTIVE)
    } else if mv == MOVE_SPEND {
        (from == STATE_ACTIVE) & ((to == STATE_ACTIVE) | (to == STATE_EXHAUSTED))
    } else if mv == MOVE_REVOKE {
        ((from == STATE_ACTIVE) | (from == STATE_EXHAUSTED)) & (to == STATE_REVOKED)
    } else if mv == MOVE_RESET {
        ((from == STATE_ACTIVE) | (from == STATE_EXHAUSTED)) & (to == STATE_ACTIVE)
    } else {
        false
    }
}

/// Take move `mv` from `from`, landing in `to` (the contract picks `to` among the declared targets, e.g. spend
/// picks `exhausted` when nothing remains). Refuses with the generated refusal when the move is not declared
/// from `from`; refuses with AL-099 when the target is not declared (a scaffold bug, never a user error).
pub fn step(from: u8, mv: u8, to: u8) -> u8 {
    if !can(from, mv) {
        errors::refuse_move(mv, from);
    }
    assert(is_edge(from, mv, to), f"[AL-099] AllowanceUndeclaredTarget {{ move: {mv}, state: {from}, to: {to} }}");
    to
}

/// The lazy `reset`: worked out on the next touch. Returns (state, spent, period) after applying `reset` if the
/// month index `now_period` is past `period`. Callers pass a period computed from a time they can trust (see
/// the contract: in private code that is the anchor block's timestamp, a lower bound on the real time).
pub fn lazy_reset(state: u8, spent: u128, period: u32, now_period: u32) -> (u8, u128, u32) {
    if (now_period > period) & can(state, MOVE_RESET) {
        (step(state, MOVE_RESET, STATE_ACTIVE), 0, now_period)
    } else {
        (state, spent, period)
    }
}

// Generated from the blueprint. Do not edit.
// `every: calendar_month` -> a month index (year * 12 + month - 1) from a unix timestamp, UTC.
// civil_from_days (H. Hinnant), unsigned-only since timestamps are >= 1970.
pub fn month_index(timestamp: u64) -> u32 {
    let days = timestamp / 86400;
    let z = days + 719468;
    let era = z / 146097;
    let doe = z - era * 146097;
    let yoe = (doe - doe / 1460 + doe / 36524 - doe / 146096) / 365;
    let doy = doe - (365 * yoe + yoe / 4 - yoe / 100);
    let mp = (5 * doy + 2) / 153;
    let m = if mp < 10 { mp + 3 } else { mp - 9 };
    let y = yoe + era * 400 + (if m <= 2 { 1 } else { 0 });
    (y * 12 + m - 1) as u32
}

// Generated from the blueprint. Do not edit.
// The allowance's private state as ONE note. Every field is `visibility: private(owner, member)`, so the note
// is encrypted to both the owner and the member, and its nullifier must be computable by BOTH roles that may
// move it (spend: member; revoke: owner). The default aztec-nr nullifier, H(note_hash, nhk_app(note owner)),
// is computable only by the note owner's keys, which would make `revoke` impossible for the grantor.
// So the target generates a custom nullifier keyed by a per-allowance secret `nullifier_key`, chosen at grant
// and shared with exactly the roles that may move the thing.
use aztec::{
    context::PrivateContext,
    macros::notes::custom_note,
    note::{note_interface::NoteHash, utils::{compute_note_hash, compute_note_nullifier}},
    protocol::{address::AztecAddress, traits::{Packable, ToField}},
};

#[derive(Eq, Packable)]
#[custom_note]
pub struct AllowanceNote {
    pub owner: AztecAddress,
    pub member: AztecAddress,
    pub limit: u128,
    pub spent: u128,
    pub period: u32,
    pub state: u8,
    pub nullifier_key: Field,
}

impl NoteHash for AllowanceNote {
    fn compute_note_hash(self, owner: AztecAddress, storage_slot: Field, randomness: Field) -> Field {
        let data = self.pack().concat([owner.to_field(), randomness]);
        compute_note_hash(storage_slot, data)
    }

    fn compute_nullifier(
        self,
        _context: &mut PrivateContext,
        _owner: AztecAddress,
        note_hash_for_nullification: Field,
    ) -> Field {
        compute_note_nullifier(note_hash_for_nullification, [self.nullifier_key])
    }

    unconstrained fn compute_nullifier_unconstrained(
        self,
        _owner: AztecAddress,
        note_hash_for_nullification: Field,
    ) -> Option<Field> {
        Option::some(compute_note_nullifier(note_hash_for_nullification, [self.nullifier_key]))
    }
}

    fn grant(member: AztecAddress, limit: u128) {

        // Refusal from the owner's view of the state (an honest PXE). Constrained guarantee below.
        let existing = self.storage.allowances.at(member).get_notes(

        );
        let state = if existing.len() == 0 { STATE_NONE } else { existing.get(0).note.state };
        let to = machine::step(state, MOVE_GRANT, STATE_ACTIVE);

        let secret = self.context.request_nhk_app(owner_npk_m_hash);

// Generated from the blueprint. Do not edit.
// target-noir, Effect client for `allowance` over the aztec.js artifact (src/artifacts/Allowance.ts).
//
// Every operation runs on the CALLER'S DEVICE (`runs: "client"`): the caller's own PXE executes the private
// function, proves it, and submits the proven tx. Each operation is one span with four child steps:
//   request -> sync -> prove (execute + Chonk proof, the `prove` step kind) -> submit -> wait
// `sync` is required: the PXE executes against its last synced block (the ANCHOR). Without it, a second move
// right after a first one runs against stale private state (it re-reads a note that is already nullified).
// Refusals are decoded from the assertion message `[AL-xxx] Name { field: value }` into typed errors.
import { Context, Effect, Layer, Schema } from "effect"
import type { AztecAddress } from "@aztec/aztec.js/addresses"
import { waitForTx } from "@aztec/aztec.js/node"
import type { AztecNode } from "@aztec/aztec.js/node"
import { AllowanceContract } from "../artifacts/Allowance.js"

// ---------- states (same numbering as the Noir target) ----------
export const AllowanceState = { none: 0, active: 1, exhausted: 2, revoked: 3 } as const
export type AllowanceStateName = keyof typeof AllowanceState
export const stateName = (n: number): AllowanceStateName =>
  (Object.keys(AllowanceState) as AllowanceStateName[]).find((k) => AllowanceState[k] === n) ?? "none"

// ---------- visibility table (from the blueprint) ----------
// private(owner, member): only those two devices may hold the value. Nothing private goes into spans or logs.
export const Visibility = {
  fields: { owner: "private", member: "private", limit: "private", spent: "private", period: "private", state: "private" },
  args: { grant: { member: "private", limit: "private" }, spend: { owner: "private", member: "private", amount: "private" }, revoke: { owner: "private", member: "private" } },
  refusalPayload: { AllowanceCannotGrant: { state: "private" }, AllowanceCannotSpend: { state: "private" }, AllowanceCannotRevoke: { state: "private" }, AllowanceExceeded: { remaining: "private" } },
} as const

// ---------- refusals ----------
export class AllowanceCannotGrant extends Schema.TaggedError<AllowanceCannotGrant>()("AllowanceCannotGrant", { state: Schema.Number }) {}
export class AllowanceCannotSpend extends Schema.TaggedError<AllowanceCannotSpend>()("AllowanceCannotSpend", { state: Schema.Number }) {}
export class AllowanceCannotRevoke extends Schema.TaggedError<AllowanceCannotRevoke>()("AllowanceCannotRevoke", { state: Schema.Number }) {}
export class AllowanceExceeded extends Schema.TaggedError<AllowanceExceeded>()("AllowanceExceeded", { remaining: Schema.BigInt }) {}
export class AllowanceNotOwner extends Schema.TaggedError<AllowanceNotOwner>()("AllowanceNotOwner", {}) {}
export class AllowanceNotMember extends Schema.TaggedError<AllowanceNotMember>()("AllowanceNotMember", {}) {}
/** The network refused the proven tx (e.g. a nullifier already exists: double spend / replay). */
export class NetworkRejected extends Schema.TaggedError<NetworkRejected>()("NetworkRejected", { reason: Schema.String }) {}
/** Anything else. The message is NOT kept (it may contain private values); only a fixed category is. */
export class AztecFailure extends Schema.TaggedError<AztecFailure>()("AztecFailure", { step: Schema.String }) {}

export type AllowanceRefusal =
  | AllowanceCannotGrant | AllowanceCannotSpend | AllowanceCannotRevoke | AllowanceExceeded
  | AllowanceNotOwner | AllowanceNotMember

const REFUSAL = /\[AL-(\d{3})\] (\w+) \{ ?(.*?) ?\}/
export const decodeRefusal = (message: string): AllowanceRefusal | undefined => {
  const m = REFUSAL.exec(message)
  if (!m) return undefined
  const fields: Record<string, string> = {}
  for (const kv of m[3].split(",").map((s) => s.trim()).filter(Boolean)) {
    const [k, v] = kv.split(":").map((s) => s.trim())
    fields[k] = v
  }
  switch (m[2]) {
    case "AllowanceCannotGrant": return new AllowanceCannotGrant({ state: Number(fields.state) })
    case "AllowanceCannotSpend": return new AllowanceCannotSpend({ state: Number(fields.state) })
    case "AllowanceCannotRevoke": return new AllowanceCannotRevoke({ state: Number(fields.state) })
    case "AllowanceExceeded": return new AllowanceExceeded({ remaining: BigInt(fields.remaining) })
    case "AllowanceNotOwner": return new AllowanceNotOwner()
    case "AllowanceNotMember": return new AllowanceNotMember()
  }
  return undefined
}
const NETWORK = /(nullifier|Nullifier)[^"\n]{0,80}/
const toFailure = (step: string) => (e: unknown): AllowanceRefusal | NetworkRejected | AztecFailure => {
  const msg = String((e as any)?.message ?? e)
  // device-local debugging only: never on by default, never exported (the raw message may hold private values)
  if (process.env.ARCHITECT_DEVICE_DEBUG) console.error(`[device-debug] ${step}: ${msg.slice(0, 600)}`)
  const refusal = decodeRefusal(msg)
  if (refusal) return refusal
  const n = NETWORK.exec(msg)
  if (n && step === "submit") return new NetworkRejected({ reason: n[0].slice(0, 80) })
  return new AztecFailure({ step })
}

// ---------- the redaction rule ----------
// Span attributes are an ALLOWLIST. Allowed: the operation, the step kind, where it runs, the role, timings,
// circuit sizes, and the outcome TAG (never a refusal payload). Device-only attributes (tx hash) are kept on
// the caller's device and stripped by `exportable` before anything leaves it: on Aztec a tx hash is public, so
// "tx X was a spend by the member" would de-anonymise an on-chain tx that otherwise reveals neither.
export const ALLOWED_ATTRIBUTES = new Set([
  "architect.thing", "architect.operation", "architect.step", "architect.runs", "architect.role",
  "architect.outcome", "aztec.witgen_ms", "aztec.proving_ms", "aztec.functions", "aztec.gates",
  "device.tx_hash",
])
export const DEVICE_ONLY = new Set(["device.tx_hash"])
export const exportable = (attrs: ReadonlyMap<string, unknown>) =>
  Object.fromEntries([...attrs].filter(([k]) => !DEVICE_ONLY.has(k)))
const safe = (attrs: Record<string, unknown>) => {
  for (const k of Object.keys(attrs)) if (!ALLOWED_ATTRIBUTES.has(k)) throw new Error(`redaction: attribute ${k} is not allowlisted`)
  return attrs
}

// ---------- the client ----------
export interface AllowanceView { readonly state: AllowanceStateName; readonly limit: bigint; readonly spent: bigint; readonly period: number }
export interface StepTimings { prove: { witgenMs: number; provingMs: number; totalMs: number }; submitMs: number; waitMs: number; totalMs: number }
type OpResult = { txHash: string; timings: StepTimings }
type OpError = AllowanceRefusal | NetworkRejected | AztecFailure

export interface AllowanceClientShape {
  readonly grant: (member: AztecAddress, limit: bigint) => Effect.Effect<OpResult, OpError>
  readonly spend: (owner: AztecAddress, member: AztecAddress, amount: bigint) => Effect.Effect<OpResult, OpError>
  readonly revoke: (owner: AztecAddress, member: AztecAddress) => Effect.Effect<OpResult, OpError>
  readonly read: (owner: AztecAddress, member: AztecAddress) => Effect.Effect<AllowanceView, AztecFailure>
  /** prove without submitting: returns a submit effect (used to show a replayed/double spend is refused). */
  readonly proveSpend: (owner: AztecAddress, member: AztecAddress, amount: bigint) => Effect.Effect<Effect.Effect<OpResult, OpError>, OpError>
}

/** One client per device: `wallet` is that device's wallet (its own PXE, its own keys), `from` its account. */
export class AllowanceClient extends Context.Service<AllowanceClient, AllowanceClientShape>()("architect/AllowanceClient") {}

export interface DeviceConfig { readonly wallet: any; readonly node: AztecNode; readonly from: AztecAddress; readonly contract: AztecAddress; readonly role: "owner" | "member" | "other" }
export class Device extends Context.Service<Device, DeviceConfig>()("architect/Device") {}

const ms = (t0: number) => Math.round((performance.now() - t0) * 10) / 10

export const AllowanceClientLive = Layer.effect(AllowanceClient, Effect.gen(function* () {
  const d = yield* Device
  const contract = AllowanceContract.at(d.contract, d.wallet)
  const w = d.wallet as any

  const prove = (op: string, interaction: any) =>
    Effect.gen(function* () {
      const payload: any = yield* Effect.tryPromise({ try: () => interaction.request(), catch: toFailure("request") })
        .pipe(Effect.withSpan(`allowance.${op}.request`, { attributes: safe({ "architect.step": "request", "architect.runs": "client" }) }))
      yield* Effect.tryPromise({ try: () => w.pxe.sync(), catch: toFailure("sync") })
        .pipe(Effect.withSpan(`allowance.${op}.sync`, { attributes: safe({ "architect.step": "sync", "architect.runs": "client" }) }))
      const t0 = performance.now()
      const proven: any = yield* Effect.tryPromise({
        try: async () => {
          const fee = await w.completeFeeOptions({ from: d.from, feePayer: payload.feePayer })
          const req = await w.createTxExecutionRequestFromPayloadAndFee(payload, d.from, fee)
          return w.pxe.proveTx(req, { scopes: w.scopesFrom(d.from, []), senderForTags: w.senderForTagsFrom(d.from) })
        },
        catch: toFailure("prove"),
      }).pipe(
        Effect.tap((p: any) => Effect.annotateCurrentSpan(safe({
          "aztec.witgen_ms": Math.round((p.stats?.timings?.perFunction ?? []).reduce((a: number, f: any) => a + f.time, 0)),
          "aztec.proving_ms": Math.round(p.stats?.timings?.proving ?? -1),
          "aztec.functions": (p.stats?.timings?.perFunction ?? []).length,
        }))),
        Effect.withSpan(`allowance.${op}.prove`, { attributes: safe({ "architect.step": "prove", "architect.runs": "client" }) }),
      )
      const proveMs = ms(t0)
      const t = proven.stats?.timings ?? {}
      const witgenMs = (t.perFunction ?? []).reduce((a: number, f: any) => a + f.time, 0)
      const submit = Effect.gen(function* () {
        const tx: any = yield* Effect.tryPromise({ try: async () => proven.toTx(), catch: toFailure("submit") })
        const txHash = (yield* Effect.tryPromise({ try: async () => tx.getTxHash(), catch: toFailure("submit") })) as any
        const t1 = performance.now()
        yield* Effect.tryPromise({ try: () => d.node.sendTx(tx), catch: toFailure("submit") }).pipe(
          Effect.withSpan(`allowance.${op}.submit`, { attributes: safe({ "architect.step": "submit", "architect.runs": "client", "device.tx_hash": txHash.toString() }) }))
        const submitMs = ms(t1)
        const t2 = performance.now()
        yield* Effect.tryPromise({ try: () => waitForTx(d.node, txHash, { interval: 0.25 } as any), catch: toFailure("submit") }).pipe(
          Effect.withSpan(`allowance.${op}.wait`, { attributes: safe({ "architect.step": "wait", "architect.runs": "chain" }) }))
        const waitMs = ms(t2)
        return { txHash: txHash.toString(), timings: { prove: { witgenMs, provingMs: t.proving ?? NaN, totalMs: proveMs }, submitMs, waitMs, totalMs: 0 } }
      })
      return submit
    })

  const run = (op: string, interaction: any) =>
    Effect.gen(function* () {
      const t0 = performance.now()
      const submit = yield* prove(op, interaction)
      const r = yield* submit
      r.timings.totalMs = ms(t0)
      return r
    }).pipe(
      Effect.tapError((e) => Effect.annotateCurrentSpan(safe({ "architect.outcome": e._tag }))),
      Effect.tap(() => Effect.annotateCurrentSpan(safe({ "architect.outcome": "ok" }))),
      Effect.withSpan(`allowance.${op}`, { attributes: safe({ "architect.thing": "allowance", "architect.operation": op, "architect.runs": "client", "architect.role": d.role }) }),
    )

  return {
    grant: (member, limit) => run("grant", contract.methods.grant(member, limit)),
    spend: (owner, member, amount) => run("spend", contract.methods.spend(owner, member, amount)),
    revoke: (owner, member) => run("revoke", contract.methods.revoke(owner, member)),
    proveSpend: (owner, member, amount) => prove("spend", contract.methods.spend(owner, member, amount)).pipe(
      Effect.withSpan("allowance.spend", { attributes: safe({ "architect.thing": "allowance", "architect.operation": "spend", "architect.runs": "client", "architect.role": d.role }) })),
    read: (owner, member) => Effect.tryPromise({
      try: async () => {
        const { result } = await contract.methods.get_allowance(owner, member).simulate({ from: d.from })
        const [s, limit, spent, period] = result as [bigint, bigint, bigint, bigint]
        return { state: stateName(Number(s)), limit, spent, period: Number(period) }
      },
      catch: () => new AztecFailure({ step: "read" }),
    }).pipe(Effect.withSpan("allowance.read", { attributes: safe({ "architect.thing": "allowance", "architect.operation": "read", "architect.runs": "client", "architect.role": d.role }) })),
  }
}))
