## The idea

Orthograph is a framework where you describe a system once and everything else is made from that description. You
write the description as TypeScript declarations in a [`blueprint`](blueprint.mdx) folder, and `ortho check` compiles
it to a model. **Each operation is enforced in exactly one place**: the wrapper on the Worker for an operation written
in Effect, or the contract for one that runs on a chain. Everything else falls out of the model and reaches that one
place: the SDK, the CLI, MCP tools and actions for the apps people build, and the [portal](portal.mdx) for the builder
who needs to understand the running system. Each of those is a **projection**: one view of the same model, made by
code, never written by hand. The one thing a description can't say is what an operation actually does. So the rule
is: **behaviour is the only freehand**. Each operation's body is a [handler](handlers.mdx) you write; everything
around it is generated, and stays generated. **The loop** is how the pieces meet: you describe, the model compiles,
journeys prove it, environments ship it, and what is missing or red comes back as new work.

## The smallest example

This is the sign-up sheet's `join`, declared in the blueprint. It says what joining is, and nothing about how it is
done:

```ts file=examples/signup/blueprint/things/sheet/verbs/join.ts name=default lines=7-17
export default Blueprint.operation(Sheet, {
  description: "Take places on a sheet, for yourself and anyone with you.",
  payload: { sheet: Sheet.fields.id, people: Count },
  answer: { left: Count },
  move: machine.moves.join,
  errors: [SheetFull],
  allowed: [Blueprint.anyone],
  steps: { load: Blueprint.step.database(), record: Blueprint.step.database() },
  idempotent: "request", // sent twice with one request, it takes its places once
  budget: { p95: "150 millis" },
});
```

From those eleven lines Orthograph makes every way in. Each file opens with a line saying it was generated and must
not be edited. The HTTP endpoint takes its route, payload, answer and refusals from the declaration:

```ts file=examples/signup/generated/api/src/sheet/join.ts name=imports,endpoint lines=1-14
// Generated from blueprint/things/sheet/verbs/join.ts. Do not edit.
import { HttpApiEndpoint } from "effect/http-api";
import { wireStruct } from "orthograph/server";
import declaration from "../../../../blueprint/things/sheet/verbs/join.ts";
import { SheetFull, SheetNotOpen, SheetNotFound, IdempotencyConflict } from "../errors.ts";

export { declaration };
export const endpoint = HttpApiEndpoint.post("join", "/sheet/join", {
  payload: declaration.payloadSchema,
  // What the wire carries: the declared answer, the fields not every caller is shown optional. The server cuts each answer by who is asking.
  // Typed as the declaration types it: the schema is built from fields known only at run time, which TypeScript cannot follow.
  success: wireStruct(declaration.answer, { issuing: true }) as unknown as typeof declaration.answerSchema,
  error: [SheetFull, SheetNotOpen, SheetNotFound, IdempotencyConflict],
});
```

One of those refusals was never written: `SheetNotOpen` comes from the machine. The rest of what `join` becomes:

| Projection | What it makes for `join` | Where |
|---|---|---|
| server | the served operation: the one wrapper that enforces `sheet.join` | `examples/signup/generated/server/main.ts:28` |
| SDK | `join(payload)` | `examples/signup/generated/sdk/src/sheet/join.ts:8` |
| CLI | the command `sheet join --sheet … --people …`, built on the SDK | `examples/signup/generated/cli/src/sheet/join.ts:9` |
| MCP | the tool `sheet.join`, described by the declaration | `examples/signup/generated/mcp/src/index.ts:12` |
| docs | its page: who may call, budget, payload, refusals with their codes | `examples/signup/generated/docs/sheet/join.md:38` |
| handler type | what the handler is given and may return | `examples/signup/generated/api/src/sheet/join.handler.ts:7` |
| action | a `defineAction` in agent-native's field names, built on the SDK | planned, M1.22 ([doors](doors.mdx)) |

Every one of them reaches the same served operation; none of them checks anything on its own. What each door is, and
why it holds no authority, is [doors](doors.mdx).

And this is the only part of `join` someone wrote. Orthograph scaffolded it once, from the declaration; from then on it
is yours:

```ts file=examples/signup/src/sheet/join.ts name=imports,default lines=1-27
// Scaffolded from blueprint/things/sheet/verbs/join.ts. Yours from now on.
import { Effect } from "effect";
import { Records } from "@orthograph/language-effect";
import type { Handler } from "../../generated/api/src/sheet/join.handler.ts";
import { Sheet } from "../../blueprint/things/sheet/thing.ts";
import { SheetFull } from "../../blueprint/things/sheet/errors.ts";

/** Take places on a sheet, for yourself and anyone with you. */
const join: Handler = ({ sheet, people }, { steps, move }) =>
  Effect.gen(function* () {
    const records = yield* Records;
    // The machine's check already found the sheet open, so it exists.
    const found = yield* steps.load(records.find(Sheet, sheet));
    if (!found) return yield* Effect.die(new Error(`sheet ${sheet} was checked and then not found`));
    const places = found["places"] as bigint;
    const taken = found["taken"] as bigint;
    const left = places - taken;
    if (people > left) {
      yield* Effect.logInfo("more people than places left").pipe(Effect.annotateLogs({ people: String(people), left: String(left) }));
      return yield* new SheetFull({ left });
    }
    yield* steps.record(records.update(Sheet, sheet, { taken: taken + people }));
    yield* move(people === left ? "full" : "open");
    return { left: left - people };
  });

export default join;
```

The handler counts the places, records the join and picks the next state. It never checks who is calling or whether
the sheet is open, never parses a request and never names a route. The declaration already said all of that.

## How it works

Read it top to bottom; each band has its own page in this layer:

1. **The blueprint** is what you write ([blueprint](blueprint.mdx)). Plugins are mounted into it: features, adapters
   and projections ([plugins](plugins.mdx)).
2. **The model** is what `ortho check` compiles it to: one JSON, every declaration hashed. Every projection is made
   from it, never from the blueprint directly.
3. **Languages** turn the model into frames, blanks and the enforcer for each place an operation can run. **Hosts**
   are where that runs ([languages-and-hosts](languages-and-hosts.mdx)). The right-hand column, the chain, is
   illustrative until K7 settles how an operation maps to a contract.
4. **Data** lives in stores the framework owns, in sources it reaches through adapters, and in views kept from events
   ([data](data.mdx)).
5. **The doors** all go through the generated SDK or straight to the served operation, so the one enforcer decides
   every time ([doors](doors.mdx)).
6. **Evidence** comes back under the model's names, and proof and the portal read the same structure the declaration
   drew.

The loop runs through those bands in the order a change moves:

1. **You describe.** You and your agent write declarations under `blueprint/`. Built. Plugins mounted into the
   blueprint come in M1.06.
2. **It compiles.** `ortho check` compiles the blueprint to the model and checks types, rules and drift. Built.
   Blanks and journeys join the model in M1.03.
3. **Projections make the outputs.** The generators render `generated/` from the model. Built. If a generated file
   differs from what the model renders, `ortho check` fails, so nobody can edit one and keep it.
4. **Handlers fill in behaviour.** `ortho generate` scaffolds a handler for each operation, once, and never
   overwrites it ([handlers](handlers.mdx)). Built; the wired scaffold is M1.26.
5. **Journeys prove it.** A different agent writes [journeys](journeys.mdx) through the real operations. `ortho prove`
   runs them in a world, the nine evals judge the evidence, and a verdict is recorded ([proof](proof.mdx)). Built.
6. **Environments ship it.** `ortho promote` moves one exact build from environment to environment
   ([environments](environments.mdx)). Built locally; the cloud is M7.
7. **The loop closes.** The [factory](factory.mdx) turns blanks, red verdicts and drift into tasks, and only a fact
   closes one (M3.09). Until then, you close the loop yourself: you read what `ortho check` and `ortho prove` say, and
   act on it.

## Choices

**Declaration or handler?** Put it in the declaration whenever the declaration can say it. Each thing a declaration
says is generated into every door, enforced in one place, checked and traced. Each thing a handler does is only in
that handler.

| You want to say | Say it in | Because |
|---|---|---|
| who may call | the operation's `allowed` | the enforcer refuses before the handler runs, whichever door the call came through |
| a state it must be in | the machine's move | the refusal is generated |
| a way it can fail | the operation's `errors` | it gets a code, an exit code, a typed error in the SDK and a docs row |
| how it decides and what it writes | the handler | only behaviour is freehand |

**Generated client or your own?** Use the generated SDK, CLI, MCP tools and actions. Each is remade when the blueprint
changes, and each reaches the same enforcer. A hand-written client drifts the day an operation changes.

## What it is not

- **Not a one-off code generator.** Generated files are never yours. They are remade from the model, and editing one
  fails `ortho check`. Only scaffolds become yours ([handlers](handlers.mdx)).
- **Not low-code.** A handler is ordinary Effect code. Orthograph takes away the code around behaviour, not behaviour.
- **Not the blueprint.** Orthograph is the framework and its command. The [blueprint](blueprint.mdx) is what you write
  with it.
- **Not a host.** Orthograph makes what runs; a host such as Cloudflare runs it
  ([languages-and-hosts](languages-and-hosts.mdx)).
- **Not an agent-native app.** Orthograph ports what it needs from agent-native into its own Effect code and keeps
  agent-native's action field names, so its templates read naturally. Nothing of agent-native runs, and there is no
  dependency on it (K5, "Porting from agent-native"). The details are on [doors](doors.mdx) and [portal](portal.mdx).
- **Not a list of data places.** Where data lives, and who may write it, is [data](data.mdx).
