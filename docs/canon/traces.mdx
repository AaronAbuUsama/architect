## The idea

A trace is what one call leaves behind, as a tree of timed pieces called spans. You never write span code: the
operation's declaration makes the spans. The operation opens one span named after it, once the caller has passed the
role check. Each declared step opens a child, and the commit opens one more. Only fields the declaration makes public
are written on a span, so the declaration decides what a trace may say. One rule makes traces readable: **a refusal
ends its span OK and a defect ends it in error**, so red always means something broke, never that a caller was told
no.

## The smallest example

This is acme's `spend`. Nothing in it mentions tracing:

```ts file=examples/acme/blueprint/things/allowance/verbs/spend.ts name=default lines=8-18
export default Blueprint.operation(Allowance, {
  description: "Spend from what is left of this month's allowance.",
  payload: { allowance: Allowance.fields.id, amount: Amount, memo: Memo },
  answer: { remaining: Amount },
  move: machine.moves.spend,
  errors: [AllowanceExceeded],
  allowed: [grantee],
  steps: { load: Blueprint.step.database(), record: Blueprint.step.database() },
  idempotent: "request", // retried with the same request key, it spends once
  budget: { p95: "150 millis" },
});
```

The compiler has already worked out each span's name. This is rendered from acme's compiled model:

From that, one call leaves this trace. The two steps are the two children, named `<operation>.<step>`, and the
attributes come from the payload, the answer and the caller:

```text planned=M1.18
allowance.spend          principal.person=per_olga  payload.allowance=alw_1  payload.amount=120  answer.remaining=380  attempt=1
├─ allowance.spend.load    step.kind=database
├─ allowance.spend.record  step.kind=database
└─ allowance.spend.commit  step.kind=commit  commit.writes=1  commit.entries=1  commit.outcome=committed
```

The last line, `attempt`, and the missing `payload.memo` are the designed trace (M1.18 and M1.19). Today the commit
has no span of its own, and `payload.memo=train` is written.

Journeys assert on spans by name, so a trace is checked, not just looked at. When the spend is refused, the
`record` step never ran, and the journey says so:

## How it works

### The order a call runs in

<Scene name="handler-lifecycle" caption="Watch where each refusal leaves: two before the operation's span opens, the rest inside it, ending OK." />

1. **The payload is decoded.** A payload that doesn't fit is refused as `InvalidPayload` before anything else runs,
   so it leaves no span (`packages/language-effect/src/modules/handler/service.ts:104`).
2. **The role is checked.** A caller the role refuses gets `NotAllowed`, still before the operation's span opens, so a
   stranger never looks like work (`service.ts:46`).
3. **The operation's span opens**, named after the operation, with the caller on it:

   ```ts file=packages/language-effect/src/modules/handler/service.ts name=serve lines=83
   spanned(name, { operation: name, ...principalAttributes(principal) }),
   ```

4. **The payload is written on it**, public fields only (`service.ts:50`).
5. **Each step is its own span**, marked with its kind:

   ```ts file=packages/language-effect/src/modules/handler/service.ts name=serve lines=30-36
   const steps = Object.fromEntries(
     // Each step is its own span, marked with its kind: a `database` step's work is the store's, a `wait` step's a timer's.
     Object.entries(op.steps).map(([key, step]) => [
       key,
       <A, E, R>(work: Effect.Effect<A, E, R>) => spanned(`${name}.${key}`, { "step.kind": step.type })(work),
     ]),
   );
   ```

6. **The answer is written on it** before it is checked, so an answer outside its declaration is evidence `prove` can
   name (`service.ts:62`).
7. **The commit runs.** Today it runs inside the operation's span but not as a span of its own (gap 1, below).
8. **The outcome is written on the span.** A defect gets `defect`; a refusal gets `refusal` and, when the handler
   logged something just before refusing, `refusal.log`:

   ```ts file=packages/language-effect/src/modules/handler/service.ts name=serve lines=77-82
   Effect.tapCause((cause) =>
     Cause.hasDies(cause)
       ? Effect.annotateCurrentSpan({ defect: Cause.pretty(cause).split("\n")[0] ?? "" })
       : logs.last.pipe(Effect.flatMap((log) =>
           Effect.annotateCurrentSpan({ refusal: tagOf(Cause.squash(cause)), ...(log === undefined ? {} : { "refusal.log": log }) }))),
   ),
   ```

### Refusal and defect

A refusal is an outcome the operation was built to give: a declared error such as `AllowanceExceeded`, a move from the
wrong state, a role that said no. A defect is a failure nothing declared: a bug, a store that failed, an answer that
broke its own declaration. Effect would end a span in error for both, so every span goes through `spanned`, which ends
it OK for a typed failure and in error only when the work dies:

```ts file=packages/language-effect/src/modules/handler/internal/span.ts name=spanned lines=10-15
export const spanned = (name: string, attributes: Record<string, unknown>) => <A, E, R>(work: Effect.Effect<A, E, R>): Effect.Effect<A, E, R> =>
  work.pipe(
    Effect.result,
    Effect.withSpan(name, { attributes }),
    Effect.flatMap((outcome) => (Result.isFailure(outcome) ? Effect.fail(outcome.failure) : Effect.succeed(outcome.success))),
  );
```

The failure still leaves the span unchanged, so the caller gets its typed refusal. Only the span's colour differs.

| | Refusal | Defect |
|---|---|---|
| What it is | a declared outcome: the operation said no | an undeclared failure: something broke |
| The span ends | OK, tagged `refusal` (and `refusal.log`) | in error, tagged `defect` |
| The caller gets | the declared error, with its code and exit code | a failure outside the declared errors, which no client can match |
| Who acts | nobody: it worked | a person, or the factory as a `fix` task |

### What a span may say

What a span says is an allowlist built from the declaration. A field's value is written only when the declaration
names the field and makes it public:

```ts file=packages/language-effect/src/modules/handler/internal/attributes.ts name=publicOnly lines=10-11
export const publicOnly = (values: object, fields: FieldsInput): Array<[string, unknown]> =>
  Object.entries(values).filter(([k]) => Object.hasOwn(fields, k) && fields[k]!.visibility === "public");
```

A secret or private field is never written, and neither is anything the declaration doesn't name, so a new kind of
field fails closed. The caller is written as `principal.person`, or `principal.kind` when there is no person
(`attributes.ts:17`).

### What to look for

<Scene name="trace-waterfall" caption="A real allowance.grant trace from prove, building span by span: the role check's read before the operation's span, then the step, then the commit's batch." />

- **Red is a defect, and only a defect.** Refusals are tagged, not red.
- **A missing child shows where the call stopped.** `spend.load` without `spend.record` means it was refused after
  the read.
- **`attempt` above 1**, after a commit with `commit.outcome=conflict`, is a version race. Many of them mean
  contention on one thing (see `stores`).
- **`request.replayed=true`** is a retry with the same request key that changed nothing (`service.ts:54`).
- **Each step's width against the budget** shows which step is slow. `spend` must answer within `p95: "150 millis"`.

To read one trace, `ortho telemetry trace <id>` prints it as a tree from the Collector's files, a refusal marked
`refused` and a defect marked `✘ defect`. It needs no viewer and works over SSH. `ortho telemetry view` starts the
local viewer.

### Where it goes

The core speaks only OpenTelemetry. Where it goes is an environment's `telemetry` list of sinks, so one sink or
several is the same line:

```ts file=packages/orthograph/src/modules/telemetry/types.ts name=TelemetryApi lines=23-28
export interface TelemetryApi {
  readonly sink: {
    readonly local: () => Sink;
    readonly axiom: (spec: { readonly group: string }) => Sink;
  };
}
```

`Telemetry.sink.local()` is the Collector that `prove` and `env up` start, and the viewer when it runs. It needs no
credential. `Telemetry.sink.axiom({ group })` sends to the `<group>-traces` and `<group>-logs` datasets.

## The three gaps, and how each is fixed

Found while reading the handler wrapper (O2). Each is one slice of M1, and each ends in the check named.

### Gap 1: the commit has no span (M1.18)

**Today.** `store.commit(…)` runs inside the operation's span but not as a span of its own:

```ts file=packages/language-effect/src/modules/handler/service.ts name=serve lines=71-72
const committed = yield* store.commit({ writes: yield* unit.writes, entries, ...request });
if (committed === "conflict") return yield* new Conflict();
```

A slow D1 write, or a commit that lost its version race, shows only as a longer `spend`. In the real trace above, the
commit appears only as D1's own `BATCH` span, with nothing naming it. A rerun after `conflict` shows as a second
`spend` span beside the first, with nothing saying why.

**The fix.** The commit becomes `<operation>.commit`, tagged `step.kind: "commit"`, with `commit.writes` and
`commit.entries` as counts (never values) and `commit.outcome` as `committed` or `conflict`. The operation's span
carries `attempt`, from 1 to 64.

**Proved by** a handler test that forces one conflict and asserts both spans and both attributes, and a journey that
asserts `spans({ present: ["allowance.spend.commit"] })`.

### Gap 2: free text is traced by default (M1.19)

**Today.** Visibility is public by default
(`packages/orthograph/src/modules/visibility/types.ts:1`), and public fields become attributes. Acme's memo is free text:

```ts file=examples/acme/blueprint/values/money.ts name=Memo lines=5-6
/** What a spend was for, in a few words. */
export const Memo = Blueprint.value(Blueprint.text());
```

So "lunch" and "hotel" are written to every trace, and so is anything a person types into a text field. That is where
personal details turn up.

**The fix.** Free text is not traced unless it is marked. A public `Blueprint.text()` value is still answered to
callers and kept in events; it is never written as a span attribute or a log annotation. To trace one, mark it:

```ts planned=M1.19 path=blueprint/values/reference.ts
export const Reference = Blueprint.traced(Blueprint.value(Blueprint.text({ max: 32 })));
```

Ids, amounts, enums, booleans and times stay traced when public: they are what you search traces by, and they don't
carry what people type. No journey changes, because events keep the field.

**Proved by** the attributes test (`internal/attributes.test.ts`) asserting `payload.memo` is absent and a traced text
field is present, and the built-in "leaks nothing" eval asserting no untraced text in any span.

### Gap 3: a call refused before its span leaves no count (M1.20)

**Today.** A bad payload and a caller the role refuses leave no span. That is deliberate: a refused caller must never
look like work. But nobody can see that `spend` refused 400 strangers in an hour.

**The fix.** Every call is counted as a metric, whether or not a span opened:

- `ortho.calls`, a counter tagged `operation`, `outcome` (`answered`, `refused` or `defect`), `refusal` and
  `principal.kind`. No payload values, and no person.
- `ortho.call.duration`, a histogram per operation, to compare against the declared budget.

Both go through Effect's `Metric` to OpenTelemetry, into the `<project>-<env>-metrics` dataset O1 reserved. Locally
they go through the Collector, which gains a metrics pipeline.

**Proved by** a world test that sends one bad payload and one stranger, then reads `ortho.calls` from the Collector:
two refusals and no spans.

## Choices

### Which fields to trace

| | Public (the default) | Public text, marked `Blueprint.traced` | Secret or private |
|---|---|---|---|
| Answered to callers | yes | yes | over MCP: secret never, private only to its roles. Over HTTP, the SDK and the CLI: sent (see the note `answers-are-not-redacted`) |
| Kept in events | yes | yes | no |
| Written on spans | yes, except free text (from M1.19) | yes | never |
| Pick it when | ids, amounts, states, times | short codes you search by, never what people type | passwords, tokens, keys, anything personal |

Mark text traced only when it is a code you search by. If a person typed it, leave it untraced.

### Which sink

| | `Telemetry.sink.local()` | `Telemetry.sink.axiom({ group })` |
|---|---|---|
| Needs | Docker for the viewer; nothing for the files | a token, read from the keychain or CI, never written in the blueprint |
| Use it for | worlds, `prove`, `ortho dev` | staging and production |
| Read with | `ortho telemetry trace`, the local viewer | Axiom's trace view; `ortho watch` |

## What it is not

- **Not the journal.** An event is a fact the system keeps, with its fields, and views are built from it. A span is
  evidence of how a call ran, and it can be sampled or dropped. See `machines`.
- **Not logs you write.** A handler may log, and the last log before a refusal is kept as `refusal.log`, but the span
  tree comes from the declaration, not from your logging.
- **Not a place for personal details.** What a span may say is decided by visibility. See `things`.
- **Not the verdict.** Spans are evidence. Evals judge them, and only CI writes a verdict. See `proof`.
- **Not metrics.** Spans exist only for calls that got past the role check. Counts of every call are `ortho.calls`.

<Note kind="question" id="attempts-as-siblings" slice="M1.18">
  Each attempt opens its own operation span, so a call that raced twice shows as two `spend` spans side by side, joined
  only by `attempt`. Should the attempts be children of one parent span for the call, so a reader sees one call, not
  two? That changes the root span's name, which journeys assert on.
</Note>

<Note kind="question" id="traced-text-in-events" slice="M1.19">
  Untraced text is still kept in events, and views are built from events. Does a view that a projection renders (the
  portal, MCP) need the same rule, or is that the visibility of the view's own fields?
</Note>

<Note kind="status" slice="M1.18">
  Today the commit shows only as D1's own `BATCH` span, and a version race shows as two operation spans with nothing
  saying why.
</Note>

<Note kind="question" id="answers-are-not-redacted">
  A field's visibility keeps it off spans and out of events everywhere, but it is redacted from an answer only over
  MCP. The HTTP API, the SDK and the CLI send every declared field (D3 #125, `design/decisions/D3.md:911`), and acme's
  sign-in answers its secret fields on purpose (D3 #80). This page owns what is traced, not what is answered; the
  question of answers is [things](things.mdx)' note `private-over-http`. No slice owns the fix yet.
</Note>
